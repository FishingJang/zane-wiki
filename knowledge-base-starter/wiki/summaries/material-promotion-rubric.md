# Material Promotion Rubric

## 目的
这页回答一个非常具体的问题：

**一份新材料入库后，什么时候只停在 `routed`，什么时候可以升到 `seeded`，什么时候必须 `parked`，什么时候才值得进入 `compiled`？**

它不是讲知识库哲学，而是给日常入库与升级提供最小判断清单。

## 默认流程
1. 先入 `raw/`
2. 完成路由，进入 `routed`
3. 判断是否具备 seed 条件
4. 不具备则进入 `parked`
5. 具备 seed 条件且形成最小入口页，则进入 `seeded`
6. 形成可导航 wiki 页面网络后，才进入 `compiled`

## 四个关键状态怎么判

### `routed`
最低条件：
- 来源明确
- 路由明确
- 原件可追溯
- 中间层或说明文件存在

它只表示：材料已经被系统正确接住。

### `seeded`
至少应满足大部分：
- 能看出明确主题，而不只是书名或标题
- 能提炼出 2–4 个值得延伸的问题方向
- 能说明它和当前主库或候选支线的关系
- 能解释为什么现在还不该直接做完整 topic
- 已经有足够正文或内容线索支撑判断

### `parked`
适用情况：
- OCR / 抽取质量太弱，正文不足
- 与当前主线关系弱
- 只有单点材料，无法形成主题网络
- 当前没有明确输出价值
- 若强行升级，会导致伪整理、空判断或低质量 wiki

`parked` 不是失败，而是一种明确决策。

### `compiled`
通常应满足：
- 已有 topic / concept / case / summary 中至少一种稳定页面
- 已接入索引或导航
- 能和现有 wiki 页面形成链接关系
- 页面不是一次性摘要，而是可复用知识节点
- lint / health 检查通过

## OCR 弱材料怎么处理
默认不要升 seed，当出现以下信号时：
- `extracted_chars` 明显异常偏低
- 抽取结果主体是元数据、目录或杂讯
- 章节正文几乎不可见
- note 层无法支持主题判断

正确动作：
1. 保持 `parked`
2. 写清为什么现在不升
3. 真要推进时先补 OCR / 清洗
4. 拿到足够正文后再重评

## 最小工作准则
1. 先路由，再判断
2. 没有正文支撑，不做假 seed
3. seed 页讲升级理由，不讲空泛摘要
4. compiled 只给真正进入 wiki 结构层的内容
